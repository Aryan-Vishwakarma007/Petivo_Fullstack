PETIVO - EXPERIMENTS 6, 7 AND 8 DEMONSTRATION ORDER
==================================================

FIRST-TIME SETUP
1. Install and start Docker Desktop.
2. From the project root, copy the environment template:
       Copy-Item .env.example .env
3. Edit .env and replace DB_PASSWORD, MYSQL_ROOT_PASSWORD and JWT_SECRET
   with private values. JWT_SECRET must contain at least 32 bytes.
4. To provision an administrator on a new database, set both
   PETIVO_ADMIN_EMAIL and PETIVO_ADMIN_PASSWORD in .env. Leave both empty
   if no administrator bootstrap is required. User accounts can register
   through the application.
5. Do not share or commit .env.

START AND VERIFY DOCKER
1. From the project root, validate the Compose configuration:
       docker compose config
2. Build the backend and frontend images:
       docker compose build
3. Start all services:
       docker compose up -d
4. Check readiness:
       docker compose ps
   MySQL, backend, and frontend should report running/healthy.
5. Inspect startup logs if needed:
       docker compose logs --tail=100
6. Open:
       http://localhost:8080

EXPERIMENT 6 - JWT AUTHENTICATION
1. Register a new standard user through the Register form.
2. Sign in and confirm the protected dashboard loads.
3. In browser developer tools, inspect the Network panel. Confirm the login
   request returns a token, then inspect a protected request and confirm it
   includes an Authorization: Bearer header. Do not capture or share the
   token value.
4. Run the backend tests from a terminal:
       Set-Location backend
       .\mvnw.cmd -B test
5. Integration tests verify valid login, wrong-password rejection, protected
   access, missing/invalid/expired token rejection, and role authorization.

EXPERIMENT 7 - REACT AND SPRING BOOT API
1. In the browser, sign in with the account registered above.
2. Open Pet Grooming & Services and verify services load from the API.
3. Book an appointment and confirm it appears in Appointments.
4. Edit the appointment, refresh, then verify the saved update is still shown.
5. Delete the appointment and confirm it disappears.
6. In browser developer tools, verify requests use the same origin and
   /api paths; do not disclose Authorization token values.
7. The React production build uses VITE_API_URL=/api in Docker. The Nginx
   container forwards those requests to the backend service.

EXPERIMENT 8 - DOCKER AND GITHUB
1. In GitHub, inspect Actions after the project has been safely committed and
   pushed. Confirm the test, frontend lint/build, and Docker image build jobs
   pass. A local workflow file alone is not a GitHub Actions run.
2. After a successful push to main, check the repository owner's Packages
   for petivo-final-api and petivo-final-web.
3. GHCR image publishing is not the same as a cloud deployment. A cloud host,
   secrets, network configuration, domain, and HTTPS certificate are still
   required before a public deployment can be demonstrated.

STOP SERVICES
    docker compose down

This command preserves the mysql_data volume. Do not use `docker compose
down -v` unless database deletion is explicitly intended.
